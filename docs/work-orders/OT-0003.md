# CONTATECK · OT-0003 — Instrucciones de Despliegue
Ambiente: **Supabase DEV únicamente**. Nada de esto toca producción, Firebase, ni el Frontend actual.

---

## 0. Antes de empezar

- Este documento asume que **el equipo (no Claude)** crea el proyecto Supabase DEV desde el dashboard, porque esta sesión no tiene un conector de Supabase activo.
- Los tres scripts (`schema.sql`, `policies.sql`, `seed.sql`) se corren **en ese orden exacto**, nunca al revés — `policies.sql` referencia tablas de `schema.sql`, y `seed.sql` referencia el catálogo de roles creado en `schema.sql`.

---

## 1. Crear el proyecto Supabase DEV

1. Entrar a [supabase.com](https://supabase.com) → **New Project**.
2. Nombrarlo claramente como entorno de prueba, por ejemplo: `contateck-dev` (para no confundirlo nunca con un futuro proyecto de producción).
3. Elegir región cercana (ej. `us-east-1` o la más cercana a Tehuacán/Puebla disponible).
4. Guardar la contraseña de la base de datos que Supabase pide al crear el proyecto — se usará si conectan por `psql` directo; no es necesaria si usan el SQL Editor del dashboard.

---

## 2. Ejecutar `schema.sql`

1. En el proyecto DEV, ir a **SQL Editor** → **New query**.
2. Pegar el contenido completo de `schema.sql`.
3. Ejecutar (**Run**).
4. Verificar en **Table Editor** que aparezcan las 10 tablas: `roles`, `empresas`, `perfiles`, `cuentas_contables`, `clientes`, `productos`, `empleados`, `polizas`, `cfdis`, `auditoria_log`.

Si algo falla, lo más probable es un error de orden (una tabla referenciando otra que aún no existe) — el script ya respeta el orden aprobado en OT-0002 §10, así que un error aquí significa que no se copió el archivo completo.

---

## 3. Ejecutar `policies.sql`

1. Nueva query en el SQL Editor.
2. Pegar el contenido completo de `policies.sql`.
3. Ejecutar.
4. Verificar en **Authentication → Policies** (o en Table Editor, pestaña "RLS") que cada una de las 10 tablas tenga **RLS habilitado** y sus políticas correspondientes.

---

## 4. Ejecutar `seed.sql`

1. Nueva query en el SQL Editor.
2. Pegar el contenido completo de `seed.sql`.
3. Ejecutar.
4. Verificar en Table Editor: 5 roles, 1 empresa de prueba, 13 cuentas contables, 1 cliente, 1 producto.

---

## 5. Crear usuarios de prueba (esto sí es manual, fuera de SQL)

Para probar de verdad que RLS aísla por empresa, se necesitan **mínimo 2 usuarios en 2 empresas distintas**:

1. En **Authentication → Users → Add user**, crear un usuario de prueba (ej. `prueba1@contateck.mx`).
2. Copiar el UUID que Supabase le asigna.
3. En el SQL Editor, vincularlo a la empresa de prueba del seed:
   ```sql
   insert into perfiles (id, empresa_id, rol_id, nombre, email)
   values (
     '<uuid-del-usuario-1>',
     '00000000-0000-0000-0000-000000000001',
     (select id from roles where nombre = 'director'),
     'Usuario de prueba 1',
     'prueba1@contateck.mx'
   );
   ```
4. Crear una **segunda empresa** de prueba (con su propio `insert into empresas (...)`, distinto id) y un **segundo usuario** vinculado a ella, repitiendo los pasos 1-3.

---

## 6. Prueba de aislamiento (lo más importante de esta OT)

1. Generar un token de sesión para el Usuario 1 (puede ser desde el dashboard de Supabase, sección **Authentication → Users**, usando "Impersonate" si el plan lo permite, o desde un cliente de prueba con `supabase-js` haciendo login con ese correo).
2. Con ese token, hacer un `select * from empresas` y un `select * from cfdis` — debe devolver **solo** la empresa/datos del Usuario 1.
3. Repetir con el Usuario 2 — debe ver **solo** su propia empresa, cero filas de la del Usuario 1.
4. Si algún usuario ve datos de la otra empresa, **no continuar a ninguna otra OT** hasta corregir la policy correspondiente.

---

## 7. Qué NO se hizo en esta OT (y por qué)

- **No se migraron datos de Firebase.** Este ambiente es solo para validar que el esquema y las políticas funcionan correctamente en aislamiento, antes de mover un solo dato real.
- **No se tocó el Frontend.** `auth-login.js`, `auth-guard.js`, `data-firestore.js` siguen exactamente igual — el sitio en producción sigue operando 100% con Firebase, sin ningún cambio.
- **No se tocó producción.** Todo lo anterior vive únicamente en el proyecto `contateck-dev` de Supabase.
